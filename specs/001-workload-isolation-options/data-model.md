# Data Model: Workload Isolation Options

## Workload Options

Run-scoped settings passed from the command-line entry point through the existing performance scenario.

| Field | Shape | Applies To | Validation |
|-------|-------|------------|------------|
| Custom annotations | Zero or more key-value pairs | Pod templates and VMIs | Key and value are non-empty; duplicate and tool-managed keys are rejected. |
| Runtime class | Optional name | Pods only | Must be non-empty when supplied; VM-only runs reject the option. The cluster validates availability. |
| Launch security | Optional enum: `snp`, `tdx` | VMIs only | Non-VM runs reject the option; no value other than `snp` or `tdx` is accepted. |

## Benchmark Workload

A client or server resource created during a run.

| Workload Kind | Receives Custom Annotations | Receives Runtime Class | Receives Launch Security |
|---------------|-----------------------------|------------------------|--------------------------|
| Pod | Pod template metadata | Yes | No |
| VirtualMachineInstance | VMI metadata | No | Yes |

Every created client and server workload of the applicable kind receives the same selected values.

## Managed Annotation

An annotation generated by the tool for required default or network behavior. Managed keys are reserved:
custom values cannot replace them. This prevents a custom workload setting from changing the network
topology or other required benchmark behavior.

## Validation Lifecycle

1. Parse command-line values before creating benchmark resources.
2. Reject malformed annotations, reserved-key collisions, and workload-mode incompatibilities locally.
3. Create workload resources with validated values.
4. Surface KubeVirt admission, runtime class, feature-gate, or scheduling failures as run errors; never
   treat those failures as valid benchmark results.
